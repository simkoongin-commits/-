# 심궁회 홍보 홈 제작 명세 — Manus AI 전달용

## 1. 프로젝트 목적

한양대학교 중앙 국궁동아리 **심궁회**의 공식 홍보 홈을 제작한다. 방문자가 국궁을 낡거나 무거운 전통문화로 느끼지 않고, 정제되고 현대적인 대학 동아리 활동으로 받아들이게 하는 것이 목표다.

핵심 인상은 다음 세 단어로 정의한다.

- 절제된 긴장감
- 한곳에 모이는 집중
- 함께 수련하는 따뜻한 공동체

시각적 완성도는 Apple 제품 소개 페이지처럼 여백, 큰 타이포그래피, 정교한 움직임을 사용한다. 다만 Apple 화면을 그대로 복제하지 말고, 활의 곡선·시위의 장력·화살의 직선·과녁의 중심·한지와 먹의 질감 등 **국궁만의 조형 언어**로 재해석한다.

## 2. 가장 중요한 화면 구조

홈은 여러 카드나 독립된 슬라이드가 아니다. 처음부터 끝까지 연결된 **하나의 긴 세로형 페이지**다.

- 사용자가 아래로 스크롤하면 같은 공간 안에서 배경색, 사진, 활·화살 그래픽, 텍스트가 부드럽게 이어진다.
- 각 콘텐츠 구간의 경계를 네모난 카드, 굵은 구분선, 별도 슬라이드처럼 보이게 만들지 않는다.
- 한 장면이 사라지며 다음 장면이 이어지는 연속적인 서사 구조로 만든다.
- 필요하면 일부 이미지나 텍스트를 짧게 고정하는 sticky scroll을 사용할 수 있지만, 가로 슬라이드나 스와이프 UI는 사용하지 않는다.
- 페이지 전체가 하나의 긴 포스터 또는 한 발의 화살이 날아가는 과정처럼 느껴져야 한다.

## 3. 페이지에 유지할 실제 문구

### 도입부

- 작은 문구: `한양대학교 국궁동아리`
- 큰 제목: `활을 쏘는 순간, 마음이 한곳에 모입니다.`
- 설명: `심궁회는 국궁을 함께 배우고, 꾸준히 수련하는 한양대학교 중앙동아리입니다.`

### 수련 소개

- 작은 문구: `정규 습사`
- 큰 제목: `처음이어도 함께라서 괜찮아요.`
- 설명: `기초부터 차근차근. 예비신사 교육과 정규 습사를 통해 안전하게 활을 배웁니다.`

### 공동체 소개

- 작은 문구: `심궁회의 시간`
- 큰 제목: `활 하나로 이어지는 우리의 계절.`
- 설명: `자유 습사, 대회, 그리고 함께 나누는 일상까지. 심궁회의 이야기를 만나보세요.`

### 마지막 행동 유도

- 작은 문구: `SIMKOONG ARCHERY CLUB`
- 큰 제목: `우리의 다음 화살은 당신과 함께.`
- 버튼: `궁금한 점 물어보기`
- 버튼을 누르면 기존 Q&A 탭으로 이동한다.

문구는 관리자가 나중에 앱에서 수정할 수 있어야 하므로 이미지 안에 합성하지 말고 실제 HTML 텍스트로 구현한다.

## 4. 권장 스크롤 연출

1. 첫 화면은 활을 당기기 직전의 고요함을 표현한다. 넓은 여백과 큰 제목을 사용하고, 아주 느린 카메라 이동 또는 빛의 변화만 둔다.
2. 스크롤하면 활의 곡선이나 시위가 화면을 가로지르며 다음 구간을 자연스럽게 연결한다.
3. 정규 습사 구간에서는 실제 수련 사진을 전체 배경 또는 큰 마스크 영역으로 사용한다. 사진 위 텍스트 가독성을 반드시 확보한다.
4. 공동체 구간에서는 훈련·대회·교류 사진이 한 흐름 안에서 교차하며 나타난다. 카드 캐러셀처럼 보이면 안 된다.
5. 마지막에는 화살이 중심에 도달하는 느낌으로 시선이 CTA 버튼에 모이게 한다.

애니메이션은 스크롤을 방해하거나 멀미를 유발하지 않아야 한다. `prefers-reduced-motion` 환경에서는 이동 효과를 제거하고 페이드 정도만 남긴다.

## 5. 디자인 방향

- 주조색: 심궁회 기존 청색 계열. 짙은 남청, 맑은 하늘색, 미색을 중심으로 사용한다.
- 강조색: 과녁 중심을 연상시키는 절제된 적색을 작은 포인트로만 사용한다.
- 배경: 단순 그라데이션만 반복하지 않는다. 고해상도 국궁 사진, 미세한 한지 질감, 먹의 농담, 목재와 활의 재질을 정교하게 조합한다.
- 타이포그래피: 큰 제목은 품위 있는 한글 명조 계열, 본문과 UI는 가독성 높은 고딕 계열을 권장한다.
- 활·화살·과녁을 이모지나 흔한 아이콘으로 표현하지 않는다. 직접 제작한 SVG 또는 실제 촬영 이미지를 사용한다.
- 과도한 네온, 게임 UI, 전통 문양의 반복, 관광 홍보물 같은 붓글씨 남용은 피한다.
- 모든 요소는 모바일에서도 축소판처럼 답답하지 않고, 모바일에 맞게 재배치되어야 한다.

## 6. 유지해야 할 기존 기능

- 상단 브랜드 `심궁회`
- 문의 이메일 `simkoongin@gmail.com`
- 비로그인 상태의 로그인·회원가입 버튼
- 로그인 상태의 회원 전용 버튼
- 홍보 메뉴의 `홈`, `Q&A`
- 관리자용 `홈 편집`
- Q&A 화면과 회원 전용 화면의 기존 로직

`게시물` 탭은 사용하지 않으므로 새 디자인에 포함하지 않는다. 인증, 회원 데이터, Firebase 구조, Q&A 기능은 수정하지 않는다.

## 7. 반응형 및 품질 기준

- 기준 화면: 모바일 390×844, 태블릿 768px, 데스크톱 1440px
- 모바일과 데스크톱 모두 전체 폭을 활용한다.
- iOS Safari와 Android Chrome에서 동일한 흐름으로 동작해야 한다.
- 이미지 때문에 첫 화면이 늦게 나타나지 않도록 AVIF 또는 WebP와 반응형 크기를 제공한다.
- 첫 화면 핵심 이미지 외에는 lazy loading을 적용한다.
- 텍스트 대비는 WCAG AA 이상을 목표로 한다.
- 키보드 포커스, 버튼 이름, 이미지 대체 텍스트를 제공한다.

## 8. Manus AI에서 받아야 할 결과물

현재 서비스가 Next.js + React + TypeScript이므로, **스크린샷이나 배포 링크만 받으면 안 된다.** 아래 결과물을 모두 요청한다.

### 필수

1. React/TypeScript 원본 컴포넌트
2. 컴포넌트에 필요한 CSS 원본
3. 사용한 모든 이미지의 WebP 또는 AVIF 원본
4. 직접 만든 아이콘·활·화살 그래픽의 SVG 원본
5. 사용한 글꼴 이름, 굵기, 라이선스 정보
6. 모바일 390px 및 데스크톱 1440px 완성 화면
7. 스크롤 애니메이션 구현 코드
8. 에셋별 출처 및 상업적·비상업적 사용 가능 여부

### 가장 좋은 전달 형태

- GitHub의 별도 브랜치 또는 ZIP 파일
- 권장 파일 구성:

```text
PromoHome.tsx
promo-home.css
public/promo/*.webp
public/promo/*.svg
DESIGN-NOTES.md
```

- 외부 라이브러리를 사용했다면 패키지 이름과 정확한 버전을 `DESIGN-NOTES.md`에 기록한다.
- Figma 링크가 있다면 함께 받되, Figma만 받고 구현 코드를 생략하지 않는다.

## 9. 데이터 연결 규칙

홈의 각 문구와 선택적 배경 이미지는 배열 데이터로 전달받아 표시할 수 있어야 한다. 문구를 컴포넌트 내부에 여러 번 하드코딩하지 않는다. 현재 앱의 `PromoScene` 데이터를 새 연속형 레이아웃에 연결할 수 있도록 설계한다.
